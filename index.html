Understand the algorithm
How the six stages work
  1. Start with the input array.
  2. Split the array into left and right halves.
  3. Recursively split until each portion contains one element.
  4. Compare the first unconsumed elements of two sorted halves.
  5. Append the smaller element, copy any remainder, and copy the merged buffer back.
  6. Finish when the root range has been merged into a sorted array.
Complexity, stability, and counters
Time: O(n log n) in the best, average, and worst cases for this implementation. Each recursion level processes O(n) elements and there are O(log n) levels. Auxiliary algorithm space: O(n), with an O(log n) recursion stack.
Merge Sort is stable here: ties choose the left element first. It is not an in-place sort; it uses temporary buffers. “Comparisons” counts element-to-element comparisons. “Array writes” counts elements copied from completed buffers back into the main array.
The simulator stores extra snapshots for backward navigation. That teaching overhead is separate from the sorting algorithm’s space complexity.
Try these experiments
Use 5, 2, 5, 1, 2 to check stability; 1, 2, 3, 4 for sorted input; 9, 7, 5, 3, 1 for reverse order; and -4, 0, -9, 2 for negative values. A single element immediately reaches the base case.
